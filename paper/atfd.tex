% ABSTRACT
% ==========================================================================
\begin{abstract}
Agent workflows built on large language models are deployed in
business-critical settings, yet no benchmark comparatively evaluates the
\emph{heterogeneous monitoring tools}---heuristics, configured platforms,
and LLM judges---that practitioners use to detect failures in these
workflows.
Existing benchmarks evaluate agent capability; concurrent work benchmarks
LLM-based trace analysis~\citep{trail2025}, trains specialized
detectors~\citep{trajad2025,silentfailures2025}, and diagnoses individual
failures~\citep{agentrx2026}. None evaluates production monitoring
tools---spanning heuristics, configured observability platforms, and LLM
judges---with cost and configuration effort as first-class metrics.
We introduce \atfd (Agent Trajectory Failure Detection), a benchmark that
fills this gap with: (1)~a 7-category, 24-subcategory failure taxonomy
including quality degradation and prompt injection; (2)~a multi-domain
corpus of {2,577} trajectories from \taubench, \swebench, hand-crafted
synthetic scenarios, ATBench, Toolathlon, and
AgentRx~\citep{agentrx2026}; and (3)~a comparative evaluation
of 7 systems across 6 domains---a naive heuristic,
two open-weight LLM judges, Claude Sonnet~4, GPT-5, and two observability
platforms (LangSmith and Braintrust) each configured with 4 hand-authored
rules---measured on detection rate, false positive rate, cost, and
configuration effort.
Our initial evaluation reveals complementary detection profiles: the naive
heuristic achieves high detection on structural failures in coding
trajectories; LLM judges detect semantic failures that heuristics miss;
configured platforms are bottlenecked by their authored rules.
Claude Sonnet~4 is the only system with non-zero detection across all six
domains, achieving the highest category alignment on synthetic data
(CA = 0.545 on 150 trajectories) and the only non-zero quality degradation
detection rate (QDR = 20.6\%), though with escalating false positive rates
on harder domains. No single system dominates all cells of the evaluation matrix,
suggesting that ensemble approaches combining structural and semantic
detection warrant further investigation.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

Large language model (LLM) agents are transitioning from research prototypes
to production systems that execute consequential business workflows:
customer service interactions, software engineering tasks, financial
analysis, and legal due diligence~\citep{zenml2025production}. This
transition brings an urgent need: when an agent fails---by executing the
wrong action, producing incomplete analysis, or violating an operational
policy---someone or something must detect the failure before it propagates.

The observability landscape has responded. Commercial platforms such as
LangSmith, Langfuse, Arize Phoenix, and Braintrust now offer trace
visualization, LLM-as-judge evaluation, and anomaly detection for agent
workflows. Academic work has proposed moving beyond black-box benchmarking
toward runtime analytics of agentic systems~\citep{moshkovich2025beyond}.
Yet a fundamental question remains unanswered: \emph{how well do these
monitoring tools actually work?}

Existing benchmarks evaluate agent \emph{capability}~\citep{jimenez2024swebench,
yao2025taubench, zhou2024webarena}. Concurrent work benchmarks LLM trace
analysis~\citep{trail2025} or trains specialized
detectors~\citep{trajad2025,silentfailures2025}, but none evaluates the
full spectrum of monitoring tools---heuristics, configured platforms, and
LLM judges---that production deployments use.

Production multi-agent systems report 41--87\% failure
rates~\citep{zenml2025production,cemri2025mast}, yet monitoring tools have
no benchmark against which to be measured.

\subsection*{Why This Benchmark Is Necessary}

The cost of undetected agent failures is not hypothetical. In July 2025,
Replit's AI coding agent executed a \texttt{DROP TABLE} command during a
declared code freeze, destroying months of production data for 1,200+
users.\footnote{Fortune, July 2025.} Attorneys submitted court filings
with entirely fabricated case citations (\emph{Mata v. Avianca}, S.D.N.Y.,
2023). Deloitte documented systematic quality failures in AI-generated M\&A
due diligence---technically complete reports that omitted regulatory and
antitrust risk~\citep{deloitte2025hallucinations}. Air Canada was held
legally liable for its chatbot fabricating a bereavement fare policy
(Canadian Civil Resolution Tribunal, 2024).

These incidents span our failure taxonomy: safety violations, hallucinated
facts, quality degradation, and policy violations. Each was plausibly
detectable from the agent's trajectory alone. \atfd exists to measure
whether monitoring tools can perform this detection. The current benchmark
domains do not directly replicate these incidents; they motivate why
trajectory-level monitoring matters.

We address this gap with \atfd (Agent Trajectory Failure Detection), a
benchmark that evaluates monitoring tools rather than agents.
Our contributions are:

\begin{enumerate}[leftmargin=2em]
  \item \textbf{Failure taxonomy.} A 7-category, 24-subcategory taxonomy of
    agent trajectory failures (\S\ref{sec:taxonomy}), grounded in prior
    failure analysis work~\citep{cemri2025mast, winston2025taxonomy,
    microsoft2025taxonomy} and extended with \emph{quality degradation} as a
    first-class category and \emph{prompt injection} as a safety subcategory.

  \item \textbf{Task definition.} A formal specification of the failure
    detection task (\S\ref{sec:task}): given a complete trajectory, produce
    structured findings with severity, failure category, and step-level
    attribution, along with a mandatory cost report.

  \item \textbf{Multi-domain dataset.} A corpus of {2,577}
    trajectories (\S\ref{sec:datasets}) spanning customer service
    (\taubench retail, airline, and telecom), coding (\swebench, 100
    OpenHands trajectories), 150 hand-crafted synthetic scenarios covering
    all 7 failure categories including quality degradation, ATBench (1,000
    agent safety trajectories), Toolathlon (100 long-horizon multi-tool
    trajectories), and AgentRx (115 failed trajectories with step-level
    annotations from~\citet{agentrx2026}). AgentRx is included in the
    released corpus for future attribution and category evaluation but
    excluded from the current 6-domain detection matrix because it
    contains only failed trajectories, making FPR and F1 undefined.

  \item \textbf{Ground truth.} Binary pass/fail labels from programmatic
    verdicts (\taubench state comparison, \swebench test suites, ATBench and
    Toolathlon evaluation labels) and hand-crafted labels for synthetic
    trajectories. We additionally describe a multi-source LLM-judge
    consensus protocol for category-level annotation
    (\S\ref{sec:ground_truth}), which is planned but not yet executed;
    current evaluation uses binary detection metrics.

  \item \textbf{Comparative evaluation.} A 7-system $\times$
    6-domain evaluation (\S\ref{sec:systems}--\S\ref{sec:results})---a naive
    heuristic baseline, two open-weight LLM judges (Llama~3.3~70B,
    Llama~4~Scout), two proprietary LLM judges (Claude Sonnet~4, GPT-5),
    and two observability platforms (LangSmith and Braintrust) each
    configured with 4 hand-authored rules---with McNemar's tests for
    pairwise significance and multi-judge Fleiss' $\kappa$ for consensus
    validation.

  \item \textbf{Open benchmark harness.} A reproducible evaluation framework
    with cost-aware metrics, confidence intervals, and statistical tests,
    released as open-source software.\footnote{Code and data:
    \url{https://github.com/REDACTED/atfd} (anonymized for review).}
\end{enumerate}

% 2. RELATED WORK
% ==========================================================================
\section{Related Work}
\label{sec:related}

\atfd draws on and extends five streams of prior work: agent benchmarks,
LLM evaluation methods, agent failure analysis, trajectory-level failure
detection, and runtime monitoring.

\subsection{Agent Benchmarks}
\label{sec:related:benchmarks}

A rich set of benchmarks evaluates agent \emph{capability}:
\taubench~\citep{yao2025taubench} (customer service, \passk reliability),
$\tau^2$-bench~\citep{sierra2025tau2bench},
\swebench~\citep{jimenez2024swebench} (2,294 GitHub issues),
AgentBench~\citep{liu2024agentbench} (8 environments),
AgentBoard~\citep{ma2024agentboard} (progress-rate metrics motivating
\atfd's three-tier outcome),
WebArena~\citep{zhou2024webarena} (10--14\% agent success),
GAIA~\citep{mialon2024gaia} (92\% human vs.\ 15\% AI), and
ToolLLM~\citep{qin2024toolllm} (16,000+ APIs).
All evaluate agents, not monitoring tools. \atfd repurposes their
trajectories for a meta-evaluation: can a monitoring system detect
the failure mode?

\subsection{LLM Evaluation Methods}
\label{sec:related:llmjudge}

The LLM-as-judge paradigm~\citep{zheng2023judging} ($>$80\% human agreement
but with position, verbosity, and self-enhancement biases) provides
\atfd's methodological foundation. G-Eval~\citep{liu2023geval} shows
structured rubrics improve alignment, informing \atfd's quality rubrics.
\citet{gu2024llmjudge} catalog 8+ bias types and recommend multi-judge
consensus, which \atfd adopts for ground truth.

\subsection{Agent Failure Analysis}
\label{sec:related:failure}

MAST~\citep{cemri2025mast} introduces a 14-failure-mode taxonomy validated
on 1,600+ traces ($\kappa$=0.88); \atfd extends MAST with quality
degradation and single-agent coverage.
\citet{kami2025fail} identify tool-error recovery as the dominant failure
pattern. Agent-SafetyBench~\citep{zhang2024agentsafetybench},
\citet{winston2025taxonomy}, Microsoft~\citep{microsoft2025taxonomy},
AGENTSAFE~\citep{agentsafe2025}, and \citet{vadlamudi2026taxonomy} provide
complementary taxonomies. ToolFuzz~\citep{toolfuzz2025} informs \atfd's
synthetic generation methodology.
OWASP~\citep{owasp2025agentic}, AgentLeak~\citep{agentleak2026}, and
incident data~\citep{responsibleai2025incidents} (56.4\% year-over-year
increase) document the production risk landscape.

\subsection{Trajectory-Level Failure Detection}
\label{sec:related:trajectory}

A growing body of concurrent work addresses failure detection at the
trajectory level, each from a distinct angle.
TRAIL~\citep{trail2025} benchmarks LLM \emph{capability} at trace analysis:
148 annotated traces with 841 errors across a 20-category taxonomy
(best model: 11\% joint accuracy), but evaluates only models---not
heuristic tools or configured platforms.
TrajAD~\citep{trajad2025} generates 60,000 trajectories via
perturb-and-complete and trains a specialized anomaly detector (85\% F1).
\citet{silentfailures2025} label 4,275 multi-agent trajectories and train
ML classifiers reaching 96--98\% accuracy on silent failure detection.

Trajectory Guard~\citep{trajectoryguard2026} proposes a Siamese Recurrent
Autoencoder achieving F1 of 0.88--0.94 on trajectory anomaly detection
with 17--27$\times$ faster inference than LLM-judge baselines. Unlike
\atfd, it trains a specialized model rather than evaluating existing
production tools.

AgentPex~\citep{agentpex2026} extracts behavioral rules from agent system
prompts and checks execution traces for specification violations, evaluated
on 424 traces across \taubench domains. AgentPex automates rule
\emph{generation} from prompts; \atfd evaluates rule-driven platforms with
\emph{hand-authored} rules to measure the configuration effort gap.
Near-Miss~\citep{nearmiss2026} (ToolGuard) identifies latent policy
failures---cases where agents bypass required policy checks yet reach
correct outcomes---finding 8--17\% of tool-calling trajectories contain
such hidden failures. AgentFixer~\citep{agentfixer2026} presents 15
failure-detection mechanisms covering input handling, prompting, and output
generation, plus root-cause analysis recommending concrete fixes.
AgentProp-Bench~\citep{agentpropbench2026} evaluates judge reliability on
2,000 tasks, finding basic automated judges perform near chance level and
documenting $\sim$62\% error propagation rates---directly relevant to
\atfd's evaluation of judge systems.

AgentRx~\citep{agentrx2026} takes a diagnostic approach:
given a failed trajectory, it pinpoints the critical failure step and
category using an automated framework on 115 trajectories across
3 domains. AgentCompass~\citep{agentcompass2025} claims to be the ``first
evaluation framework for post-deployment monitoring.''
\atfd differs from both in evaluating \emph{heterogeneous} system types
(heuristics, platforms, LLM judges) with cost and configuration effort as
first-class metrics across a multi-domain corpus.

For prompt injection, InjecAgent~\citep{injecagent2024}
benchmarks indirect prompt injection attacks in tool-integrated agents, and
WASP~\citep{wasp2025} extends this with end-to-end web agent security
evaluation (attacks succeed in up to 86\% of cases). \atfd's
\texttt{safety.prompt\_injection} subcategory complements both by
evaluating whether \emph{monitoring tools} can detect injection attempts
in trajectories, rather than testing agent resilience.

The key distinction: TRAIL, TrajAD, Trajectory Guard,
\citet{silentfailures2025}, AgentRx, AgentPex, and AgentCompass evaluate
or train \emph{specific models and frameworks}; \atfd evaluates
\emph{deployed tools}---heterogeneous systems spanning heuristics,
configured platforms, and LLM judges---with cost and configuration effort
as first-class metrics.

\subsection{Runtime Monitoring and Agent Observability}
\label{sec:related:monitoring}

\citet{moshkovich2025beyond} propose observability-driven analytics for
agentic systems; \atfd provides a concrete benchmark for evaluating whether
such tools work. \atfd's task is analogous to conformance checking in
process mining~\citep{vanderaalst2016process};
\citet{berti2025llmprocess} validate that LLMs can perform this with
appropriate prompting. Surveys~\citep{survey2025eval, review2025agent} and
CLEAR~\citep{clear2025} confirm the gap; practitioner
analyses~\citep{arize2024failures, inkeep2025context, zenml2025production,
simmering2025reliability} document the production failure landscape.

\section{Agent Trajectory Failure Taxonomy}
\label{sec:taxonomy}

We propose a failure taxonomy comprising 7 top-level categories and 24
subcategories (Table~\ref{tab:taxonomy}). The taxonomy is designed to be
\emph{exhaustive} (every observed trajectory failure maps to at least one
subcategory), \emph{non-overlapping at the category level} (categories
represent distinct failure dimensions), and \emph{actionable} (each
subcategory suggests a specific remediation strategy).

\paragraph{Relationship to prior taxonomies.}
The action, process, and safety categories overlap substantially with
MAST~\citep{cemri2025mast}, Microsoft's taxonomy~\citep{microsoft2025taxonomy},
and the tool-failure taxonomy of \citet{winston2025taxonomy}.
\atfd's primary extension is the \texttt{quality} category with 5
subcategories. Prior work treats quality degradation as ``technically
correct''---and therefore not a failure. We argue that in production
deployments, a shallow analysis that covers 2 of 8 relevant risk factors
\emph{is} a failure, even if the agent did not crash, call the wrong tool,
or violate a policy. The \texttt{quality} category captures this class of
failures that matter to practitioners~\citep{arize2024failures,
inkeep2025context} but are missed by binary pass/fail evaluation.

\paragraph{Taxonomy validation.}
We validated the taxonomy against three data sources: (1)~failure annotations
from \taubench and \swebench trajectories, (2)~the MAST failure mode
catalog~\citep{cemri2025mast}, and (3)~practitioner incident reports from
Arize~\citep{arize2024failures} and Responsible AI
Labs~\citep{responsibleai2025incidents}. Every failure in these sources maps
to at least one subcategory; no source contained failures requiring a new
top-level category.

\section{Task Definition}
\label{sec:task}

The \atfd task is defined as follows.

\paragraph{Input.} A complete agent trajectory $T = (e_1, e_2, \ldots,
e_n)$ consisting of $n$ events. Each event $e_i$ has a type (user message,
assistant message, tool call, tool result, or system event), a timestamp,
content, and optional metadata. The trajectory also includes a natural
language task description.

\paragraph{Output.} A \emph{judge output} $J(T)$ consisting of:
\begin{enumerate}[leftmargin=2em]
  \item A boolean \texttt{has\_failure} flag indicating whether the
    trajectory contains any failure.
  \item A list of \emph{findings}, each specifying:
    \begin{itemize}
      \item \textbf{Severity}: \texttt{error}, \texttt{warning}, or
        \texttt{info}.
      \item \textbf{Category}: a dotted string from the taxonomy (\eg
        \texttt{action.wrong\_args}, \texttt{quality.shallow\_output}).
      \item \textbf{Description}: a natural language explanation.
      \item \textbf{Attribution} (optional): the step index or event range
        in the trajectory where the failure occurred.
    \end{itemize}
  \item A \emph{cost report} specifying dollar cost, latency in seconds,
    total tokens consumed, number of API calls, and infrastructure tier
    (none, API key, hosted service, or GPU required).
\end{enumerate}

\paragraph{Three-tier outcome model.}
Following AgentBoard's insight that binary pass/fail metrics mask meaningful
performance variations~\citep{ma2024agentboard}, \atfd defines three ground
truth outcomes:
\begin{itemize}[leftmargin=2em]
  \item \textbf{Pass}: the trajectory completes the task correctly with
    acceptable quality.
  \item \textbf{Degraded}: the trajectory produces a technically correct
    result but with substandard quality (maps to the \texttt{quality}
    category).
  \item \textbf{Fail}: the trajectory contains a hard failure in one or
    more of the remaining 6 categories.
\end{itemize}

This three-tier model enables separate measurement of hard-failure detection
(Detection Rate, DR) and quality-degradation detection (Quality Detection
Rate, QDR), revealing monitoring tools' sensitivity to subtle failures.

% 5. METRICS
% ==========================================================================
\section{Metrics}
\label{sec:metrics}

\atfd evaluates monitoring systems on seven metrics, all reported with
95\% confidence intervals.

\paragraph{Detection Rate (DR).}
Recall on \texttt{fail} trajectories: the proportion of ground-truth
failures for which the system raised at least one \texttt{error} or
\texttt{warning} finding.
\begin{equation}
  \text{DR} = \frac{|\{T : \text{gt}(T) = \text{fail} \wedge \text{detected}(T)\}|}
               {|\{T : \text{gt}(T) = \text{fail}\}|}
  \label{eq:dr}
\end{equation}

\paragraph{Quality Detection Rate (QDR).}
Recall on \texttt{degraded} trajectories: the proportion for which the
system raised at least one \texttt{quality.*} finding.
\begin{equation}
  \text{QDR} = \frac{|\{T : \text{gt}(T) = \text{degraded} \wedge \text{quality\_detected}(T)\}|}
                {|\{T : \text{gt}(T) = \text{degraded}\}|}
  \label{eq:qdr}
\end{equation}

\paragraph{False Positive Rate (FPR).}
The proportion of \texttt{pass} trajectories for which the system
erroneously raised an \texttt{error}-severity finding.
\begin{equation}
  \text{FPR} = \frac{|\{T : \text{gt}(T) = \text{pass} \wedge \text{error\_raised}(T)\}|}
                {|\{T : \text{gt}(T) = \text{pass}\}|}
  \label{eq:fpr}
\end{equation}

\paragraph{F1 Score.}
The harmonic mean of precision and recall for binary failure detection
(\texttt{fail} vs.\ \texttt{pass}/\texttt{degraded}).

\paragraph{Category Alignment (CA).}
Macro-averaged F1 across all failure categories, treating each trajectory
as a multi-label classification instance. This measures whether the system
not only detects \emph{that} a failure occurred but correctly identifies
\emph{what type} of failure it is.

\paragraph{Configuration Effort.}
A qualitative ordinal score (1--5) measuring the setup burden: API key
only, prompt engineering required, domain-specific configuration, custom
integration, or full pipeline development.

\paragraph{Cost.}
Mean dollar cost per trajectory, total cost for the full dataset,
median latency (p50), and 95th-percentile latency (p95).

\paragraph{Confidence intervals.}
All proportional metrics (DR, QDR, FPR) are reported with Wilson score
intervals~\citep{wilson1927probable}, which provide accurate coverage even
for proportions near 0 or 1 and for small samples. Aggregate metrics
(macro-F1, cost means) use bootstrap confidence
intervals~\citep{efron1993bootstrap} with 10,000 resamples. Pairwise
pairwise system comparisons will use McNemar's test with continuity
correction~\citep{mcnemar1947note} once full-scale evaluation is complete;
these tests are not reported in the current initial evaluation. Ground truth inter-rater agreement is
measured via Fleiss' $\kappa$~\citep{fleiss1971measuring}.

\paragraph{\taubench trajectories.}
We draw from \taubench~\citep{yao2025taubench}, using the retail (114
tasks $\times$ 4 trials = 456 trajectories), airline (50 tasks $\times$ 4
trials = 200 trajectories), and telecom (114 tasks $\times$ 4 trials = 456
trajectories) domains. Ground truth is derived from \taubench's
state-comparison mechanism: each task specifies expected database mutations,
and pass/fail is determined by comparing actual vs.\ expected state.
Observed failure rates are 22\% (retail), 28\% (airline), and 41\%
(telecom). The telecom domain is included in the released corpus but
excluded from the current 6-domain evaluation matrix: its 41\% failure
rate and structural similarity to retail and airline make it lower
priority than the structurally distinct domains (synthetic, ATBench,
Toolathlon) for initial evaluation. Extension to the three-tier outcome
via domain-specific quality rubrics (\S\ref{sec:ground_truth}) is
planned as future work.

\paragraph{\swebench trajectories.}
100 trajectories from \texttt{nebius/SWE-rebench-openhands-trajectories}~\citep{jimenez2024swebench}
(OpenHands v0.54.0): 50 resolved, 50 unresolved. Ground truth from
automated test suites. Failures typically contain explicit tool errors
(bash failures, test failures), making \swebench the \emph{easy} domain
for monitoring tools.

\paragraph{Synthetic trajectories.}
We hand-craft 150 trajectories covering all 7 failure categories and 24
subcategories, including categories underrepresented in real benchmarks:
quality degradation (\texttt{shallow\_output}, \texttt{suboptimal\_approach},
\texttt{incomplete\_analysis}, \texttt{poor\_tone},
\texttt{low\_confidence\_output}), safety (\texttt{prompt\_injection},
\texttt{policy\_violation}), action errors, state errors, and
infrastructure failures. Quality-degradation trajectories use the
\texttt{degraded} outcome tier, enabling QDR measurement. Of the 150
trajectories, 116 are labeled \texttt{fail} and 34 are labeled
\texttt{degraded}. Synthetic trajectories span five domains (retail,
airline, coding, finance, healthcare) and are constructed using templates
with injected failures, following the methodology of
ToolFuzz~\citep{toolfuzz2025} and
Agent-SafetyBench~\citep{zhang2024agentsafetybench}. The released corpus includes all 150 synthetic trajectories.
Table~\ref{tab:main_results} reports results on the original 50-failure
subset; Table~\ref{tab:synthetic_150} extends evaluation to the full
150-trajectory set including QDR on the 34 degraded trajectories.

\paragraph{ATBench trajectories.}
1,000 trajectories from \texttt{AI45Research/ATBench}~\citep{ai45research2025atbench}
covering agent safety scenarios (14 failure modes, 503 safe, 497 unsafe).
We evaluate on a 200-trajectory proportional sample. Failures are
\emph{semantically} defined (tool description injection, harmful actions,
data leakage) with no structural signal, making ATBench the hardest domain
for heuristic systems.

\paragraph{AgentRx trajectories.}
115 failed trajectories from \texttt{microsoft/AgentRx}~\citep{agentrx2026}
across 3 domains with step-level failure annotations (9-category taxonomy,
avg.\ 3.4 failures/trajectory). All failures; included in corpus for future
category evaluation but excluded from the detection matrix (FPR/F1
undefined).

\paragraph{Toolathlon trajectories.}
100 trajectories from \texttt{hkust-nlp/Toolathlon-Trajectories}~\citep{toolathlon2026}
(ICLR 2026): long-horizon multi-tool tasks with 600+ available tools.
We cap at 100 messages to bound cost. Of the 72 failure trajectories,
64 (88.9\%) have fewer than 100 messages in total (median: 45 messages);
only 8 (11.1\%) are truncated. The truncation confound is therefore
minimal: the overwhelming majority of failure signal resides within the
prefix that judges observe. Ground truth from
\texttt{task\_status.evaluation}.

\section{Ground Truth Validation}
\label{sec:ground_truth}

We adopt a multi-source ground truth protocol combining three sources.

\paragraph{Source 1: Programmatic verdicts (current).}
\taubench state comparison and \swebench test suite verdicts provide
high-confidence binary (pass/fail) labels. These are the sole ground truth
for all current evaluation results.

\paragraph{Source 2: LLM judge consensus (executed on synthetic).}
Three independent judges from different model families---Claude Sonnet~4
(Anthropic), Llama~4~Scout (Meta, via Groq), and GPT-5 (OpenAI, via
Codex CLI)---each classified all 150 synthetic trajectories using the
\atfd taxonomy. On binary detection (fail vs.\ non-fail), the three judges
achieve 96.0\% raw agreement (Fleiss' $\kappa$ = 0.320; the low $\kappa$
despite high agreement reflects the $\kappa$ paradox with extreme
prevalence---97\% of trajectories are flagged as failures by all judges).
On top-level failure category assignment among the 144 trajectories where
all three judges agree on ``fail,'' Fleiss' $\kappa$ = 0.557 (moderate
agreement), with 54.9\% full three-way category agreement. This
demonstrates that the 7-category taxonomy is discriminable across
independent model families.

\paragraph{Source 3: Quality rubrics (planned).}
Domain-specific rubrics~\citep{liu2023geval} with 3--5 dimensions scored
0--2 for \texttt{degraded} labeling. Currently applied only to synthetic
trajectories (by construction).

\paragraph{Circularity disclosure.}
Claude Sonnet~4 serves a dual role: both an evaluated detection system
(\S\ref{sec:systems}) and one of three consensus judges above. We mitigate
this by (1)~relying on programmatic verdicts (not LLM consensus) as
primary ground truth for all detection results, (2)~including GPT-5 and
Llama~4~Scout as independent consensus judges from different model
families, so no single model's biases dominate the consensus, and
(3)~reporting Claude's consensus contribution alongside, not instead of,
the other two judges' independent assessments.

\paragraph{Funding and access.}
This work was conducted without external funding. Groq API access used the
free tier; Anthropic API costs for Claude Sonnet~4 evaluation totaled
approximately \$12. No author has a financial relationship with any
evaluated platform.

\paragraph{Naive Heuristic.}
Rule-based baseline: error strings in tool results, timeout signals,
step-count thresholds, repeated tool calls. Zero cost, zero config. Cannot

\paragraph{LLM Judges.}
Two open-weight judges (Llama~3.3~70B, Llama~4~Scout) via Groq's free tier,
Claude Sonnet~4 via the Anthropic API, and GPT-5 via the OpenAI Codex CLI.
All receive identical two-stage prompts with the \atfd taxonomy and produce

evaluations. Confidence intervals reflect sample-size uncertainty, not

\paragraph{LangSmith and Braintrust (4-rule configurations).}
Both platforms configured with identical 4 rules ($\sim$60--80 LOC):
(1)~tool error detection (\texttt{error=True} in tool results),
(2)~tool-loop detection ($>$5 calls to same tool),
(3)~abnormal termination detection,
(4)~event-count threshold ($>$20 events).

LangSmith retail discrepancy (91.7\% vs.\ 0\% DR) results from Braintrust's
scorer firing independently on non-terminal errors, not from threshold
differences. Setup: $\sim$15 min each.

produces a partially predetermined coverage gap. These results characterize
a specific effort level, not either platform's full capability---both
support LLM-judge evaluators that could achieve performance closer to
the standalone LLM judges.

\subsection{Per-Domain Observations}

spectrum emerges: \swebench (all systems achieve 100\% DR) $\to$ Synthetic
$\to$ Retail $\to$ Airline $\to$ ATBench $\to$ Toolathlon (only Claude

coding trajectory. (3)~Airline is the hardest domain for LLM judges: even
Claude Sonnet~4 reaches only 40\% DR. (4)~No single system dominates all
cells, suggesting that ensemble approaches combining structural and
semantic detection warrant investigation.

\section{Analysis}
\label{sec:analysis}

The evaluation makes two epistemically distinct claims. On \emph{synthetic}
data, results validate rubric clarity: judges recover known labels from
designed trajectories, testing the prompt and taxonomy rather than
real-world validity. On \emph{real} data (\taubench, \swebench, ATBench,
Toolathlon), results validate ecological validity: judges detect failures
in natural trajectories with ground truth from independent programmatic
checks.

\subsection{Detection Profiles and Domain Difficulty}

profiles across system types. This complementarity is partly expected from
selecting maximally different systems; the empirical contribution is
\emph{quantifying} where each approach succeeds or fails.

Airline      & 41 / 4            & 20 / 67            & 40 / 20                  & 64 / 33 \\

The naive heuristic achieves 100\% DR / 0\% FPR on \swebench because
coding failures produce explicit tool-level errors, but only 14\% DR on
synthetic data where semantic understanding is required. LLM judges detect
100\% of synthetic failures but collapse on real \taubench domains
(Llama~4~Scout: 25\% retail, 20\% airline with 67\% FPR). Claude
Sonnet~4 bridges both profiles on some domains (100\% DR / 6\% FPR on
retail) but not uniformly (40\% DR on airline).

\paragraph{Domain difficulty spectrum.}
The six domains form a difficulty ordering: \swebench
(structural signals; all systems achieve 100\% DR) $\to$ Toolathlon
(structural signals from long trajectories; naive 79\% DR, Claude 96\%)
$\to$ Synthetic (LLM judges excel; heuristics do not) $\to$ Retail
(subtle state errors) $\to$ Airline (hardest for LLM judges) $\to$
ATBench (requires semantic safety understanding; 0\% DR for all
heuristic/rule systems). Benchmarking on any single domain would give a
misleading picture of production performance.

\subsection{Configuration Effort and Domain Calibration}
\label{sec:analysis:config}

LangSmith and Braintrust, configured with identical 4-rule sets, achieve
identical 22\% DR on synthetic---proving the detection gap is a property of
\emph{rule coverage}, not platform capability. Their rules catch only
tool-loop patterns and event-count thresholds; every semantic failure
category (hallucination, safety, communication) is missed entirely.
We acknowledge that testing 4 rules against 24 subcategories makes this
coverage gap partially predetermined; the empirical contribution is
quantifying the \emph{specific} gap and showing that both platforms produce
identical results with identical rules.

The event-count threshold exposes a pervasive calibration problem across
domains: it contributes modestly on synthetic (short trajectories) but
achieves 100\% FPR on \swebench (coding trajectories routinely exceed 20
events) and 71\% FPR on retail. The Braintrust vs.\ LangSmith retail
discrepancy (92\% vs.\ 0\% DR) results from independently calibrated
thresholds during each platform's $\sim$15-minute setup, not from
different rule logic. This fragility of threshold-based rules across
domains is a systematic finding: domain calibration is an ongoing
maintenance burden, not a one-time cost.

\subsection{Detection Difficulty by Failure Type}

Per-subcategory analysis reveals a consistent hierarchy.
\emph{Easy}: structural failures (\texttt{tool\_loop}, errors, timeouts)
detected at 100\% by heuristics on \swebench. Egregious synthetic
semantic failures detected at 100\% by LLM judges.
\emph{Moderate}: action failures (\texttt{wrong\_tool},
\texttt{wrong\_args}) require task-intent understanding; LLMs outperform
heuristics.
\emph{Hard}: quality failures (\texttt{shallow\_output},
\texttt{incomplete\_analysis}) require domain knowledge and remain the
frontier challenge~\citep{inkeep2025context, arize2024failures}.

\subsection{Error Analysis}

Common false positives: LLM judges flagging valid tool calls with unusual
argument patterns; over-flagging multi-step trajectories where intermediate
states resolve correctly; misclassifying appropriate hedging as
\texttt{low\_confidence\_output}.
Common false negatives: \texttt{wrong\_args} with numerically close values;
\texttt{partial\_state} with some correct mutations; plausible
\texttt{hallucination}.

\subsection{Limitations}
\label{sec:limitations}

\begin{enumerate}[leftmargin=2em]
  \item \textbf{Sample sizes.} LLM judges evaluated on 20--200
    trajectories per domain; small-N cells have wide confidence intervals
    (Wilson CI for 40\% DR at n=20 spans [14.7\%, 72.6\%]).

  \item \textbf{Domain coverage.} Six domains span structural, semantic,
    and multi-step failures but omit medical, financial, and legal contexts.

  \item \textbf{Ground truth.} Quality degradation labels are inherently
    subjective~\citep{groundtruth2025}. Multi-judge consensus is planned
    but not yet executed.

  \item \textbf{Temporal validity.} LLM capabilities improve rapidly;
    results may not generalize to future model versions.

  \item \textbf{Configuration sensitivity.} Platform configurations
    represent reasonable expert effort but not optimal tuning.

  \item \textbf{Synthetic circularity.} The author designed the taxonomy,
    created synthetic trajectories, and wrote judge prompts. CA scores on
    synthetic data reflect label recovery within a self-consistent system;
    independent annotation with IAA statistics is needed to validate the
    taxonomy.
\end{enumerate}

\section{Conclusion and Future Work}
\label{sec:conclusion}

We introduced \atfd, a benchmark for evaluating heterogeneous agent
monitoring systems on a unified multi-domain dataset with cost-aware
metrics. The 7-system $\times$ 6-domain evaluation on a
2,577-trajectory corpus reveals four key findings:
(1)~\textbf{No system dominates all cells}---heuristics excel on structural
failures (\swebench: 100\% DR / 0\% FPR), LLM judges on semantic failures,
and only Claude Sonnet~4 achieves non-zero DR across all six domains.
(2)~\textbf{Configuration effort matters}---rule-driven platforms achieve
identical DR with identical rules regardless of platform, proving the
bottleneck is rule coverage, not platform capability.
(3)~\textbf{Domain calibration is pervasive}---event-count thresholds
calibrated for one domain produce 100\% FPR on \swebench and 71\% FPR on
retail.
(4)~The six-domain \textbf{difficulty spectrum} ranges from structurally
trivial (\swebench) through semantically hard (ATBench) to long-horizon
hard (Toolathlon), where all systems except Claude Sonnet~4 achieve 0\% DR.
Category alignment remains below 0.5 even for the best system, indicating
that identifying failure \emph{type} is harder than detecting failure
\emph{existence}.

\paragraph{Future work.}
Immediate priorities: (1)~comprehensive rule-set configurations for
platforms (testing whether expert-authored rules close the coverage gap);
(2)~scaling LLM judge evaluation to full dataset sizes on all domains;
(3)~domain-specific quality rubrics for QDR measurement on real
trajectories; (4)~ablation studies on heuristic rules and LLM judge
prompts; (5)~ensemble evaluation combining heuristic and LLM approaches;
(6)~human annotation study for taxonomy IAA beyond the LLM-judge proxy
reported here.

\section{Judge Prompt Template}
\label{app:judge_prompt}

The following is the two-stage prompt template used for the LLM judge
systems. Stage~1 elicits an unconstrained analysis; Stage~2 maps findings
to the \atfd taxonomy.

\paragraph{Stage 1: Open Analysis.}

\begin{lstlisting}[language={},breaklines=true]
You are an expert agent trajectory analyst. You will be
given a complete agent trajectory consisting of user
messages, assistant messages, tool calls, and tool results.

Your task is to carefully analyze the trajectory and
identify ALL potential issues, failures, or quality
concerns. For each issue found, describe:
1. What went wrong
2. Where in the trajectory it occurred (step number)
3. How severe the issue is
4. What the correct behavior should have been

Be thorough. Consider action correctness, state
consistency, communication quality, process efficiency,
safety compliance, and output quality.

TRAJECTORY:
{trajectory_json}

TASK DESCRIPTION:
{task_description}
\end{lstlisting}

\paragraph{Stage 2: Taxonomy Classification.}

\begin{lstlisting}[language={},breaklines=true]
Given your analysis above, now classify each identified
issue using the ATFD failure taxonomy.

For each finding, output a JSON object with:
- "severity": "error" | "warning" | "info"
- "category": "<category>.<subcategory>" from the
  taxonomy below
- "description": one-sentence explanation
- "attribution": step number or range where the
  failure occurred

TAXONOMY:
{taxonomy_json}

Also set "has_failure" to true if ANY error or warning
finding exists, false otherwise.

Output valid JSON matching this schema:
{output_schema}
\end{lstlisting}
